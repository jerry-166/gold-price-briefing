## 金价早报自动化重复触发（当日已成功后再次运行）

### 现象
- 2026-08-27 金价早报任务（定时 9:00）未准点触发，10:25 补跑并**全流程成功**（5/5 步，daily/2026-08-27.json、manifest、git commit 5884278、邮件均已完成）。
- 10:41 自动化再次触发同一任务。若机械重跑，将导致：重复发邮件（用户收到两封相同早报）、重复 git commit、daily JSON 被覆盖、manifest 追加重复记录。

### 根因分析
- 自动化配置**无重复**（早报9:00 / 午检14:00 / 晚检22:00 各一条），排除配置重复。
- 疑为调度系统延迟/补发：9:00 触发未按时执行（可能宿主客户端未在线或调度延迟），10:25 用户或系统补跑成功；之后积压的 9:00 触发被补发到 10:41，形成"当日第二次运行"。
- 任务流程本身**缺少幂等保护**：没有在开头检查"当日 daily/YYYY-MM-DD.json 是否已生成且日志为 success"，导致重复触发时无法自愈跳过。

### 修复过程
- 本次触发：检测到 daily/2026-08-27.json 已存在 + logs/2026-08-27-morning_briefing.json 状态 success → **判定为重复触发，跳过全部执行步骤**，不重复发邮件/commit，避免数据污染。
- 后续防护建议（待落实）：在早报任务开头加入幂等检查——若当日早报日志已 success 则直接退出并提示；并将该约定写入 automation memory。

### 经验教训
- 定时任务必须幂等：开头先查"当日产物是否已存在且成功"，成功则跳过，防止调度延迟/补发造成重复执行。
- 补跑后应记录"已补跑"，供后续触发识别。
- 巡检/早报任务如遇非准点触发，需核对当日是否已有对应记录再决定是否执行。
