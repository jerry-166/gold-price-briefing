## 金价早报调度器连续多日未触发（9/1-9/4缺失、9/5延迟至16:20）

### 现象
- 2026-09-05 16:20 早报任务（定时 9:00）才被触发执行，此时已是**周六下午**。
- 检查 daily/ 目录与 git 历史：2026-09-01 至 2026-09-04 连续 4 个交易日的早报**完全缺失**（最近一次成功是 2026-08-31 09:13，commit 6972df9/fb68917）。
- 本次为 9/5 补跑成功（daily/2026-09-05.json + manifest + git 9b3d5f9/db4e9d1 + 邮件直发），但缺失的 4 天无法由本次运行自动补齐（幂等保护只覆盖"当日重复"，不覆盖"多日补跑"）。

### 根因分析
- 与 BUG-001（2026-08-27 延迟补发 10:41）及 automation memory 中多次记录的"调度器延迟问题持续"同源：**宿主侧调度器对 9:00 定时触发不可靠**，表现为准点不触发、延迟数小时甚至连续数日完全不触发。
- 记忆文件显示 2026-08-30 补跑在 23:55、2026-08-27 补跑到 10:25/10:41，本次直接跨过 4 个交易日，说明延迟问题在恶化而非偶发。
- 早报流程本身缺少"若连续 N 日未生成则告警/补齐"的兜底机制，调度失败只能靠人工或随机触发补救，无法自愈。

### 修复过程
- 本次触发：无同日产物 → 正常执行全流程（5/5 步 success），已按"周六休市取周五收盘数据"口径生成 9/5 早报并推送。
- 未能自动补齐 9/1-9/4：属调度缺失而非执行失败，逐日补齐需回填真实当日行情（成本高且无当日实时价来源），建议不回溯补生成，避免伪造历史数据。
- 建议（待宿主侧落实）：① 检查调度器为何 9:00 不触发；② 增加"距上次成功早报 >48h 未执行"时的宿主侧提醒/重推；③ 早报任务开头若发现与上次成功记录间隔超 1 个交易日，在日志与邮件中显著提示。

### 经验教训
- 调度类 bug 一旦出现延迟，不应只做"当日跳过"防护，还应主动检测"距上次成功执行的天数间隔"，间隔异常时明确告警，防止静默缺失累积成数据断档。
- 缺失的历史早报不做事后伪造（图表中已出现的 9/1-9/2 值为区间估算并在 source 中标注），宁可如实标注也不编造精确行情。
- 此类宿主侧调度问题单靠任务脚本无法根治，需持续向宿主侧反馈；每次延迟都在 automation memory 中留痕，形成时间线证据。
