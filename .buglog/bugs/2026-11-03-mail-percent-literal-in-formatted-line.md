# BUG-018 格式化字符串里的裸百分号导致拼邮件失败

## 现象

2026-11-03 早报发信前，运行 `scripts/mail_20261103.py` 抛异常：

```
TypeError: not enough arguments for format string
  P.append('...今日积存金比昨日报价高 7.4 元...今天其实微跌 0.06%，涨的是漏记的...' % C["sub"])
```

底稿 `.workbuddy/outbox/2026-11-03-morning.html` 未生成，后续 SendMessage 无内容可发。

## 根因

为解释「积存金从 844.1 跳到 851.5」，在信头说明行里补了一句「今天其实微跌 0.06%」。
该行本身是 **`%` 格式化行**（末尾带 `% C["sub"]`），而新增文字里的 `0.06%` 是一个裸百分号，
Python 把它当成又一个转换占位符，实际参数只有 1 个，于是参数数量不匹配。

这与 BUG-017 是同一枚硬币的两面：

- BUG-017：**不该写 `%%` 的字面量行**写了 `%%` → 产物里留下非法的 `width:100%%`；
- BUG-018：**该写 `%%`（或规避）的格式化行**写了裸 `%` → 直接抛 TypeError。

两次都发生在「正文需要提到百分比」的场景，判断依据只有一条：**这一行到底会不会被 `%` 格式化**。

## 修复

把该句的 `0.06%` 改写为 `0.06 个百分点`，从根上不引入百分号，而不是补 `%%`。
这样即使以后有人把这一行改成字面量行，也不会再产生 BUG-017 那种反向错误。

重新生成底稿并做回归检查：`grep -c '100%%'` ＝ 0、`grep -o 'width:100[^;]*'` 输出两条 `width:100%`。

## 教训

- 给格式化行打补丁时，**先说人话规避符号**（「0.06 个百分点」），再考虑转义（`%%`）。规避比转义安全，因为转义的正确性依赖「这行是否被格式化」这一隐性前提。
- 拼 HTML 的两套转义规则（`%` 运算符 vs 字面量）本质上不可混用。彻底解法仍是把模板层换成 replace/f-string，让百分号只作为字符存在。
- 同类坑累计三次：10/27（`-0.04%` 抛 ValueError）、11/02（BUG-017 双写）、11/03（本篇 裸写）。下次再碰「正文要写百分比」，先搜这三次记录。
