# BUG-022 hero note 格式化参数与占位符顺序错位

## 现象

2026-11-08 早报 `daily/2026-11-08.json` 首次生成后，`prices[0].note` 第三层写成：

> 按中间价 6.7168 折出来是 879.1，若按周五在岸 16:30 收盘 6.6711 折只有 **879.1**，两者差 6.0 元/克。

同一句里前后两个数字相同，却声称「差 6.0 元/克」，自相矛盾。正确值应为：中间价口径 879.1、在岸即期口径 873.1。

## 根因

`scripts/build_2026-11-08.py` 的 note 有 4 个 `%.1f` 占位符，实参传成：

```python
% (hero, hero, cny(XAU), hero - cny(XAU * 6.6711 / 6.7168))
```

第三个占位符要的是「按 6.6711 折算的人民币金价」（873.1），实际传的是 `cny(XAU)`——即乘以中间价算出的 879.1，
第四个实参（差值 6.0）又刚好与正确差值巧合一致，于是错误只在第三个数字上暴露，粗看不易发现。

## 为什么自检没拦住

`scripts/check_briefing.py` 只校验结构化字段（hero 复算、价位配对、advice 字数、引号、图表索引），
**不解析 `note` / `source` 里的自然语言数值**。这类「文案内的折算数字」只能靠人眼或专门的 note 校验脚本发现。

## 修复

改为直接传结果值，不再在实参里重复算式：

```python
% (hero, hero, hero - 6.0, 6.0)
```

并对产物做了独立复核：`round(4070.75 * 6.6711 / 31.1035, 1) == 873.1` 与文案一致。

## 后续约束

- 凡 note / source 里出现「A 折算 X、B 折算 Y、两者差 Z」的句式，写完必须用一条独立命令把 X、Y、Z 重新算一遍，
  不能依赖同一次格式化调用的输出自证。
- 多占位符且存在重复实参时，优先改成命名变量或 f-string，避免「位置对错」这类静默错误。
- `check_briefing.py` 可增补一条：note 内若出现「两者差 N 元/克」，则校验 `|前两个数字之差 - N| < 0.2`。
