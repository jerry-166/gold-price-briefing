# BUG-023 `%` 格式化串里夹带中文涨幅文案（`+1.41%`）再次触发 TypeError

- **ID**: BUG-023
- **发现日期**: 2026-11-09
- **严重度**: minor
- **状态**: fixed
- **关联**: BUG-017 / BUG-018 / BUG-019 / BUG-021（「百分号家族」第五代）

## 现象

`scripts/build_20261109.py` 首次运行，在构造 `prices[3].source`（伦敦金）时抛：

```
TypeError: not enough arguments for format string
```

指向的字符串是：

```python
'source': '新浪财经 hf_XAU 11-09 09:48 报 %s 美元/盎司（+50.20／+%s%%，昨收 4070.75…）。'
          '同上多源读数…COMEX 主力（hf_GC）4132.38（+1.41%），比现货高约 11 美元，仅作旁证不写入。'
          % (XAU, ch_xau)
```

前两个 `%s` 已正确占位、`%%` 也已转义，但**同一段拼接串后半句的 `+1.41%` 是一个裸 `%`**，
Python 把它连同后面的 `），比…` 当作一个转换规格去解析，于是「参数不够」。

## 根因

不是「不知道 `%` 要转义」，而是**写法本身把正确性押在「通读整条拼接串、找出每一个 `%`」上**。
本期这条 `source` 由 3 行 `+` 拼接而成，其中：

- 第 1 行有 2 个 `%s` 占位 + 1 个 `%%`（已转义）
- 第 3 行有一个与格式化毫无关系的字面 `+1.41%`（COMEX 旁证涨跌幅）

拼接发生在格式化之前，所以 Python 看到的是**一整条含 4 个 `%` 的字符串**，
而作者的眼睛是**逐行**读的 —— 前两行"看起来对了"，第三行的 `%` 就漏了。

与 BUG-021（整篇模板格式化）同源：**只要正文（含百分号的数字描述）与占位符共处一个被格式化的字符串，就必然漏**。
本期把它压缩到了"一条 3 行拼接的字段"，说明危害面可以小到不起眼的单个字段，防不胜防。

## 修复

把 `prices[0..3]` 的 `source` / `note` 四处从 `%` 格式化**全部改为 f-string**：

```python
'source': f'新浪财经 hf_XAU 11-09 09:48 报 {XAU} 美元/盎司（+50.20／+{ch_xau}%，…'
          f'…COMEX 主力（hf_GC）4132.38（+1.41%），比现货高约 11 美元，仅作旁证不写入。'
```

f-string 的插值边界由 `{}` 显式标出，`%` 退化为普通字符，**不需要任何转义，也不可能漏**。
仅保留 `'%.2f' % MID`（纯数值、无中文正文的短模板）。

## 教训

- **凡文案里可能出现 `%`（涨跌幅、占比、进度）的字段，一律用 f-string，不用 `%` 格式化**。
  这是本项目第 5 次因同一个决策失误付出一次运行失败，前 4 次的修法（补 `%%`、换占位注入）
  都只是"把这次的 `%` 补上"，只有换掉格式化机制才是根治。
- 判断标准可以简化成一句：**要格式化的字符串里只要有一个汉字，就改用 f-string**。
  纯数值短模板（`'%.2f' % x`）才允许 `%`。
- 一条 `source` 拼接 3 行时，`%` 的正确性检查必须**在拼接后**做（或在生成后 `grep -c '%'` 复核），
  逐行审读是无效的。
