# BUG-027 跨日折算混用今日汇率

## 现象

`build_20261119.py` 初稿用统一函数 `cny(usd, r=RATE)`（`RATE = 6.7128`，今日中间价）计算全部折算值，
包括 **昨日收盘折算基准** `cny(3724.67)`。断言立刻拦下：

```
AssertionError: 803.8633843779639   # 期望 803.7
```

正确值应为 `3724.67 × 6.7118 ÷ 31.1035 = 803.74`（**6.7118 是 11-18 的中间价**）。
误用今日汇率后，基准抬高 0.12 元/克，「今日 vs 昨收」的差从 **−2.92** 被算成 **−3.08**，
误差虽小但会让 hero note 的归因拆分（金价 −3.04 ＋ 汇率 +0.12 ＝ −2.92）整体失衡。

同类断言还连带拦下两处手算错：`cny(3700)` 写 798.4（实际 798.54，应为 798.5）、
在岸即期折算写 795.4（按今日即期 6.6664 实际 795.3）。

## 根因

「折算」这个动作在两个不同的时点被使用，但只有一个默认汇率：

- **今日本期**：金价 × **今日**中间价 → 用 6.7128；
- **昨日基准**：昨日金价 × **昨日**中间价 → 必须用 6.7118，才能和昨日早报同一口径可比。

初稿把两者都走默认参数，导致基准侧渗入今日汇率变动。

## 修复

引入 `FXP = 6.7118`（上一交易日中间价）并在所有「昨日 / 历史基准」折算处显式传入：

```
assert round(cny(3724.67, FXP), 1) == 803.7
DIFF_CLOSE = round(cny(SPOT_NOW) - cny(SPOT_PREV, FXP), 2)   # == -2.92
```

归因拆分同步改为「金价贡献用旧汇率算、汇率贡献用新金价算」，两项相加严格等于总差（有断言保证）。

## 教训

凡是「今日值 vs 昨日值」，**两侧必须各自用自己那天的汇率**；只有一个默认 `RATE` 的辅助函数是陷阱。
建议后续每个 build 脚本都显式声明 `RATE`（今日）与 `FXP`（上一交易日）两个常量，并在断言里各出现一次。
