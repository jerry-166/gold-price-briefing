## 1. 项目背景与目标

### 1.1 背景

用户是一名在校学生，同时在开发实习。当前通过招商银行黄金积存金业务买卖黄金（按克计价、可兑换实物、跟随金价波动），但存在以下痛点：

- 不懂金价变动的原因（为什么涨、为什么跌）
- 不懂发展趋势，不会判断买卖时机
- 没有金融投资知识基础
- 没有时间做深度的网络调研
- 需要通俗的"大白话"讲解，而非专业术语

### 1.2 目标

构建一个**自动化的金价资讯系统**，每天定时为用户：

1. **整合信息**：搜集金价、汇率、重大新闻，用大白话解读
2. **辅助决策**：给出趋势判断和操作建议（针对招行积存金用户）
3. **预警提醒**：发生大事或金价剧烈波动时及时通知
4. **金融教学**：每天用一个真实例子教会一个金融知识点
5. **沉淀知识**：通过网站积累历史早报和教学卡片，形成个人金融知识库

### 1.3 设计原则

- **大白话优先**：所有内容用最通俗的语言，避免专业术语
- **零额外成本**：使用 WorkBuddy 额度驱动，不额外购买 API
- **自动化**：用户配置完成后，日常无需干预
- **可升级**：模型、数据源、推送渠道均可后续扩展
- **中长期视角**：匹配招行积存金的产品特性，不鼓励频繁短线

```
┌─────────────────────────────────┐
│   WorkBuddy Automation（大脑）   │
│   用用户额度，0 额外 API 成本    │
│                                 │
│  ① 抓数据  ② AI 生成  ③ 写文件  │
└──────────────┬──────────────────┘
               │
       ┌───────┴───────┐
       ▼               ▼
   邮件推送         网站更新
   (QQ 邮箱)     (GitHub Pages)
       │               │
       └───────┬───────┘
               ▼
```

### 3.1 核心思路

不写独立程序调 API，而是利用 WorkBuddy 的**定时自动化任务**功能。WorkBuddy 本身就是 AI，自带搜索工具、文件写入工具、命令执行能力，可以一站式完成：抓数据 → 生成内容 → 写文件 → 发邮件 → 更新网站。

### 3.2 三个触发节点

| 时间 | 任务 | 说明 |
|------|------|------|
| 09:00 | 早报 automation | 生成完整早报，发邮件 + 更新网站 |
| 14:00 | 巡检 automation | 检查当日大事/大波动，有则发预警 |
| 22:00 | 巡检 automation | 同上，覆盖晚间事件 |

## 4. 核心功能设计

### 4.1 每日早报

每天 9:00 生成，结构如下：

```markdown
# 今日金价早报 | 2026-07-16 周四

## 今日金价快照
- 国际金价：$XXXX/盎司（昨夜 ±X.X%）
- 人民币汇率：X.XX（±X.X%）
- 国内金价（AU99.99）：¥XXX/克
- 招行积存金买入价：¥XXX/克

## 昨夜大事
1. 事件A → 大白话解读：为什么影响金价
2. 事件B → 大白话解读：为什么影响金价

## 趋势怎么看
- 短期（本周）：偏强/偏弱/震荡
- 给你的建议：持有/加仓/减仓/观望

## 今日学一招
用一个金融知识点，结合今天的真实例子，3 句话讲明白。
```

**设计原则**：纯小白 5 分钟能看完，看完知道今天该不该动、顺便学一个知识点。

### 4.2 定时巡检与预警

每天 14:00、22:00 各跑一次巡检。流程：

1. 用搜索工具查"今日金价新闻、重大财经事件"
2. 查当前国际金价，计算当日波动幅度
3. AI 判断是否需要预警（无需写关键词规则，AI 自主判断新闻重要性）

**预警触发条件**：
- 国际金价当日波动超过 ±1.5%
- 重大事件发生（美联储议息、CPI 数据、地缘冲突升级等）

**预警格式**（简短直接）：
```markdown
# 金价预警 | 今夜 2:30
金价短线跳水 -1.8%，原因：美国 CPI 超预期。
建议：持有不动，积存金适合中长期，别被短线吓出去。
详情：网站链接
```

无大事时静默，不打扰用户。

### 4.3 网站

纯静态网站，部署在 GitHub Pages。四个模块：

| 模块 | 内容 |
|------|------|
| 首页 | 今日早报（最新一期），底部往期列表 |
| 知识库 | 教学卡片按主题分类（美联储与金价、地缘政治与金价等） |
| 金价走势 | 过去 30 天折线图，标注关键事件点 |
| 关于 | 系统说明、数据来源、免责声明 |

**风格**：干净、大白话、手机友好。

### 4.4 知识库

每天早报中的"今日学一招"自动沉淀到知识库。按主题分类，随时间积累形成个人金融百科。

## 5. 技术实现

### 5.1 内容与样式分离架构

```
内容层（每天变）          展示层（固定不变）
┌─────────────────┐      ┌─────────────────────┐
│ daily/          │      │ index.html (模板)    │
│   2026-07-16.md │────▶│ assets/css/style.css │
│   2026-07-17.md │      │ assets/js/app.js     │
│ knowledge/      │      │                     │
│   美联储与金价.md │      │ JS 读取 MD → 渲染    │
│ manifest.json   │      └─────────────────────┘
└─────────────────┘
```

**工作原理**：
1. automation 每天写一个 Markdown 文件到 `daily/` 目录
2. automation 更新 `manifest.json`（记录所有早报元数据）
3. 网站的 JS 打开时读 `manifest.json` → 找最新 → fetch 对应 MD → 用 marked.js 渲染
4. 历史归档、知识库同理

**好处**：
- 改样式只改一处，所有历史页面自动更新
- automation 任务轻（只写 MD + JSON）
- 纯静态，GitHub Pages 完美支持
- MD 文件可复用（网站 + 邮件正文）

### 5.2 文件结构

```
每日金价资讯/
├── index.html                  # 网站首页（固定模板）
├── manifest.json               # 早报清单（automation 每天更新）
├── daily/                      # 每日早报（Markdown）
│   ├── 2026-07-16.md
│   └── 2026-07-17.md
├── knowledge/                  # 知识库（Markdown）
│   ├── 美联储与金价.md
│   └── 地缘政治与金价.md
├── assets/                     # 网站静态资源
│   ├── css/

│   ├── js/
│   │   └── app.js              # 读取 MD 并渲染
│   └── lib/
│       └── marked.min.js       # Markdown 渲染库
├── scripts/                    # 工具脚本
│   └── send_email.py           # 发邮件脚本
```

### 5.3 数据源

| 数据 | 来源 | 获取方式 | 成本 |
|------|------|----------|------|
| 国际金价 | 新浪财经/东方财富 | WebSearch / WebFetch | 免费 |
| 人民币汇率 | 中国银行/央行 | WebSearch | 免费 |
| 国内金价 | 上海金交所 AU99.99 | WebFetch | 免费 |
| 招行积存金价格 | 招商银行官网 | WebFetch | 免费 |
| 重大新闻 | 金十数据/新浪财经/央视 | WebSearch | 免费 |

### 5.4 邮件推送

使用 Python `smtplib` + QQ 邮箱 SMTP。

**流程**：
1. automation 生成早报 MD 后，调用 `send_email.py`
2. 脚本读取 `config/email.json`（收件人、授权码）
3. 把 MD 内容转成 HTML 邮件，发送到用户邮箱

**用户需准备**：
- QQ 邮箱开启 SMTP 服务，获取授权码
- 授权码存入 `config/email.json`（已 gitignore，不会泄露）

### 5.5 网站部署

GitHub Pages 部署：
1. 本地项目初始化 git，推送到 GitHub 仓库
2. 仓库 Settings → Pages → 开启（source: main 分支）
3. 访问地址：`https://用户名.github.io/仓库名/`
4. automation 每天生成内容后，执行 `git add && git commit && git push`，GitHub Pages 自动更新

## 6. Automation 设计

### 6.1 早报 Automation

| 配置项 | 值 |
|--------|-----|
| 名称 | 每日金价早报 |
| 调度 | 每天 09:00（RRULE: FREQ=DAILY;BYHOUR=9;BYMINUTE=0） |
| 工作目录 | /Users/neptune/workspace/每日金价资讯 |
| 模型 | 可切换（起步 GLM-Flash，可改 GLM-4.6） |

**Prompt 核心逻辑**：
1. 用 WebSearch/WebFetch 抓取：昨夜至今的国际金价、美元指数、人民币汇率、重大财经新闻
2. 生成大白话早报（按 4.1 节结构），写入 `daily/YYYY-MM-DD.md`
3. 提取"今日学一招"内容，追加到对应主题的知识库文件
4. 更新 `manifest.json`
5. 调用 `scripts/send_email.py` 发送邮件
6. 执行 `git add . && git commit && git push` 更新网站

### 6.2 巡检 Automation

| 配置项 | 值 |
|--------|-----|
| 名称 | 金价巡检 |
| 调度 | 每天 14:00、22:00（RRULE: FREQ=DAILY;BYHOUR=14,22;BYMINUTE=0） |
| 工作目录 | 同上 |
| 模型 | 同上 |

**Prompt 核心逻辑**：
1. 用 WebSearch 查"今日金价新闻、重大财经事件"
2. 查当前国际金价，计算当日波动
3. 判断是否需要预警（波动 >1.5% 或有重大事件）
4. 需要则生成简短预警，发邮件 + 更新网站
5. 无大事则静默结束

### 6.3 模型选择与切换

| 模型 | 特点 | 适用场景 |
|------|------|----------|
| GLM-Flash | 便宜、够聪明、讲大白话没问题 | 起步、日常使用 |
| GLM-4.6 | 分析更深、能做多事件关联 | 想升级深度分析时 |

切换方式：修改 automation 的 `modelId` 参数，无需改代码。

## 9. 风险与免责

### 9.1 风险
- **数据源不稳定**：免费接口偶尔失效，automation 应有容错（抓不到就用上一次数据 + 标注）
- **AI 判断偏差**：AI 生成的趋势判断仅供参考，不保证准确
- **邮件送达延迟**：SMTP 偶有延迟，关键预警不能100%保证实时

### 9.2 免责声明
本系统提供的所有信息（包括但不限于金价分析、趋势判断、操作建议）**仅供学习和参考，不构成任何投资建议**。用户据此操作的盈亏自负。黄金投资有风险，入市需谨慎。
